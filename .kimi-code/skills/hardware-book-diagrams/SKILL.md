# 《硬件从零到整机》插图规则

全部用项目既有组件画图：`pdfdiagram`/`block`/`waveform` 环境；节点样式 `hw state`（寄存器/状态）、`hw compute`（组合/处理）、`hw control`（控制）、`hw memory`（存储）；连线 `hw bus`（实线=数据路径）、`hw return`（虚线=控制/反馈）；文字 `hw label`；图注 `\diagramnote{...}`；晶体管级用 `hw nmos/pmos/gnd` pic。不要自造新样式。

## 一、箭头收尾（本章首总图踩过的坑）

- 箭头最后一段必须**垂直进入目标框的边框**：终点写 `(box.north)/(box.south)/(box.west)/(box.east)` 时，路径末段方向要正对该锚点。竖直下落进框顶用 `-|` 收尾，水平进框侧用 `--`。
- **禁止箭头尖沿框边滑动**：如 `(wb.east) |- (rf.south)` 的末段是水平线，箭头尖会横向贴在框底边上，读起来像流向左掠过而不是写入。正确做法：先下探到框底下方通道，再 `-|` 折向上竖直进入 `(rf.south)`。
- 反馈线进 MUX 等框时停在框边（`hw bus` 自带 shorten），**不要穿入框内**穿过框内文字。
- 画完逐条 `\draw` 自问：箭头指向与正文叙述的数据流方向一致吗？（写回→寄存器堆、下一 PC→PC、采样沿方向。本书出过时钟沿画反、箭头画反各一次。）

## 二、标签防压（9 处已修复缺陷的共同根源）

- 斜线、交叉线、回线旁的 midway 标签**一律加 `fill=white, inner sep=1pt`**（主板图三个斜线标签穿字就是这么修的）。
- 文字与线不在同一高度：波形图上"一个反相器延迟"这类标注要放在双向箭头**上方或下方**，留出净间隙；状态图转移条件标签放在箭头上方（必要时 `yshift=3pt`），不压线。
- 竖直走线旁边放标签前先算线的 x 坐标，文字带不得与线相交（NAND 图 `safe_chain_n` 穿字案例）；间隙不够就把标签整体移到线通道上方或侧方空白处。
- 波形图注释（如"复位释放"）要避开竖直虚线参考线：先确认参考线 x 位置，文字 anchor=west 放在最近一条参考线之后。

## 三、布局与走线通道

- 表头分层：卡诺图等图形表格，变量名（如 BC）与编码行（00 01 11 10）**必须不同高度**，禁止排成同一行让人误读为多出一列。
- 框底回线通道：框底 y 与图内说明文字顶 y 之间至少留 0.2cm；不够就把说明文字节点下移，不要硬挤。
- 框内多行文字与进入框边的线分开：选择器/使能标注放在线不经过的一侧。
- TikZ 坐标算术必须写 `({\x+0.85},y)`，禁止裸 `\x+0.85`（编译会炸或画错）。
- 元素不得出框、不得超出页面宽度；图宽按版心（约 12cm 内）设计，waveform 用 `x=0.8–0.9cm` 缩放。

## 四、波形图专属

- 信号名标签统一左侧 `anchor=east`；总线框（BookTeal 矩形）内写该时段稳定值；时钟沿参考虚线只画到有意义的沿。
- 时序语义必须自洽：复位在哪个沿生效、哪个周期完成取指、状态在哪个沿提交，要与正文 trace 表逐项吻合。
- 不画"死线"：全程无变化的信号要么删掉，要么换成有信息量的波形。

## 五、渲染目检（硬要求，不可省略）

1. 根目录 `make hw-pdf` 重建，确认零 `^! ` 错误、零 Overfull。
2. 每张新图/改过的图：`mutool draw -o /tmp/x.png -r 100 main.pdf <页码>` 后 ReadMediaFile 目检，重点看：箭头方向、线穿字、字压线、表头误读、出框。细节用 `region` 参数放大核对。
3. **禁止只凭坐标推算就提交**——必须看到渲染结果正常才算完成。
4. 目检通过后 `make hw-phone-export` 导出手机，再提交推送（见 book-export-workflow、repo-git-workflow 技能）。
