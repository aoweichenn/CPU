\part{操作系统对象与执行边界}

\begin{partbridge}
这一部分建立全书的对象模型与执行主线。操作系统面对的是不可信的用户请求、有限的处理器时间、需要长期保存的执行状态，以及可能延迟或失败的外部事件。内核必须把这些条件组织成可调度、可隔离、可等待和可回收的对象。

第一章从一次文件保存请求建立系统全景，说明 task、地址空间、文件对象、页缓存、设备请求和持久化边界之间的关系。随后依次讨论进程与调度、系统调用与权限、程序映像装载，以及同步、IPC 与锁。硬件原理不再单列为正文导论；涉及特权级、页表、中断、DMA 等条件时，只说明它们对当前内核机制施加的约束。

读完这一部分，读者应当能够说明：执行流的状态保存在何处，用户请求如何受控进入内核，线程为何以及如何睡眠与唤醒，程序映像在何处完成提交，共享状态由哪些同步规则保护。
\end{partbridge}

\part{地址空间与内存管理}

\begin{partbridge}
上一部分建立了执行流和受控入口；这一部分讨论地址如何获得含义、权限和生命周期。虚拟内存、page cache 和内核分配器放在一起，是因为它们共同决定页面属于谁、何时建立映射、何时回收，以及失败时哪些状态必须撤销。

虚拟内存把地址访问交给 VMA/PTE/page fault 决策；\code{mmap} 和 page cache 把文件内容、内存页面和 I/O 提交连在一起；内核分配器从 buddy 到 slab 管理物理页和内核对象。它们看似分属不同子系统，实质上都在回答同一个问题：验证在哪里完成，临时状态放在哪里，提交点是哪一行，失败后哪些对象必须回滚。

读这一部分时要始终区分三类状态：地址空间策略、页表中的当前映射，以及物理页和缓存页的实际归属。
\end{partbridge}

\part{设备、文件与网络}

\begin{partbridge}
前两部分已经建立任务、边界和内存；这一部分把它们连接到外部设备与持久数据。设备不会直接理解进程和文件，它只提供寄存器、队列、DMA 地址、中断和完成记录。内核要把这些异步事件组织成文件描述符、块请求、文件系统对象和网络端点。

设备驱动把寄存器、队列、DMA 映射和完成记录转换成可追踪的请求；块层和 VFS 再把 bio、fd、inode、page cache 和目录项组织成统一接口；文件系统把磁盘块组织成有名字、有结构且可恢复的持久对象；网络栈把网卡队列和协议状态组织成套接字语义。

这一部分的共同问题是所有权与完成边界：缓冲区当前由谁使用，完成记录对应哪个请求，错误在哪一层返回，以及接口成功是否已经达到持久化条件。
\end{partbridge}

\part{安全、持久化与系统观测}

\begin{partbridge}
最后一部分不再引入新的资源类型，而是讨论前述机制在攻击、崩溃、介质故障和性能异常下能否保持可解释性。

安全隔离要说明主体可以访问哪些对象；持久化要说明崩溃后哪些状态可以信任；错误处理要限制故障传播范围；可观测性则要说明证据的来源、适用边界和不确定性。它们共同构成操作系统机制在异常条件下的完整性要求。

读完本册，读者应当能够针对任一机制说明其状态对象、受控入口、权限规则、等待关系、提交边界、失败路径和可观察证据。
\end{partbridge}
