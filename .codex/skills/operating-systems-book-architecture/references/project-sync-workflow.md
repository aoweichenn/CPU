# 同级 OS 项目与书稿的强制同步流程

同级 `../os` 项目是《操作系统第一册》的主体架构。项目仍处于早期演进阶段，
书稿不能把某次审计得到的版本、对象或能力边界长期当作静态事实。原有正文作为
深入解释层保留，但其章节入口、承接关系和案例边界必须跟随项目演进。

## 每次调用的前置审计

1. 先运行 `scripts/audit_project_sync.py`，再规划或修改书稿。
2. 完整阅读实时项目的 `README.md`、`docs/roadmap.md`、最新已完成 release、
   当前阶段 ADR、架构/模块说明以及受影响源码和测试。
3. 运行项目已有的完整验证入口，记录通过数、失败数和未运行项；不能只依据文档
   或成功日志判断能力已经存在。
4. 区分三类事实：
   - 已完成且有构造、采用、失败和跨层证据的能力；
   - 正在实现但尚未通过完整验收的能力；
   - roadmap 中的未来设计。
5. 即使最新版本号未变化，只要核心文档、源码、测试或工具指纹变化，也要重新
   审计受影响机制；版本号相同不代表书稿仍然准确。

## 项目变化后的书稿同步范围

至少检查并按需更新：

- `frontmatter/project-spine.tex` 的当前完成边界、实际状态、失败记录、结构图、
  里程碑表和证据；
- `main.tex` 的部分顺序和部分过渡；
- 受影响章节开头的“当前机器”状态框、前章继承与下一问题；
- 项目已经实现的最小结构与正文深入结构之间的边界措辞；
- 目录、图、表、伪代码、练习和术语中已经过时的版本或能力声明。

不得删除已有深入知识单元。项目实现给出纵向主线；正文继续说明相同契约在更大
规模、更多并发、更长生命周期和更多故障条件下怎样扩展。

## 构建、检查与完成同步后的快照

书稿源文同步后，先运行：

```text
python3 .codex/skills/operating-systems-book-architecture/scripts/audit_project_sync.py --book-only
```

这个模式核对实时项目、README、roadmap、release 和书稿完成边界，但允许旧快照
仍然保持为“上一次已经发布的书稿所对应的项目状态”，因此可以继续构建和视觉
检查新 PDF。它不能代替最终的严格同步检查。

只有在以下条件全部满足后，才可更新
`references/os-project-snapshot.json`：

1. 实时项目验证已通过；
2. 书稿已反映最新完成边界和受影响实现事实；
3. 当前能力与未来路线没有混写；
4. 最终 PDF 已构建并完成相关页面的视觉检查。

运行：

```text
python3 .codex/skills/operating-systems-book-architecture/scripts/audit_project_sync.py --emit-snapshot
```

把输出写入快照文件后，再运行不带参数的同步检查。禁止为了让检查通过而只更新
快照、不更新书稿。严格检查通过后才可执行手机导出、提交和推送；如果构建或
检查期间项目指纹再次变化，重新审计、验证和构建，不能沿用刚才的结果。
