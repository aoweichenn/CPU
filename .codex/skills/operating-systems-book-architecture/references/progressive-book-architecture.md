# 《操作系统第一册》渐进式推导架构

## 不可跳过的逻辑起点

第一幅机器图只能包含硬件和一个可装入的任务，不包含 kernel、task、scheduler、system
call、VFS 等后来才会得到的对象。先说明：

- 最小机器由哪些器件组成，时钟、复位、处理器、易失内存、非易失启动存储和最小互连分别承担什么；
- 处理器怎样通过地址、读写方向和数据完成一次取指或访存，复位信号怎样让它从已知位置开始；
- 处理器从某个入口地址取指；
- 寄存器和内存保存当前计算状态；
- 程序怎样被放入内存并获得初始 PC/SP；
- 程序若直接访问全部内存和设备，机器当前没有谁替它管理资源。

整体图只展示当前真实存在的器件和连接。每当后续章节再加入计时器、中断控制、地址转换或
设备控制器，先分别建立硬件模型、软件可见模型和上层抽象，再让操作系统机制使用该抽象。
三层模型都要写出代表状态和一次具体交互，不能把硬件名称直接当成能力说明。

然后让这个单任务方案在“任务不退出、需要切换到另一个任务”这一条件下失效。为解决该
失败，推导保存/恢复执行现场；这项发展形成一章。保存现场之后仍缺少“何时切、选谁运行”，
再推导时钟事件、可运行集合和调度；这项发展形成下一章。全书始终按“当前机器 → 新问题
→ 最小新增机制 → 新机器状态”推进。

每次演进就是一个章节，不按现代 OS 名词先划章节再回填理由。硬件抽象在首次成为推导前提
时出现：先讲本章所需的可见硬件状态和动作，再讲 OS 如何利用它；不重复硬件书，也不假设
零基础读者已经理解寄存器、PC/SP、异常入口或时钟中断。

## 总体教学顺序

全书不以“完整系统全景”作为起点。读者每次只承担一个新问题：

1. 给出最小动作、现有状态和朴素做法。
2. 用一个可复算的反例说明朴素做法失效。
3. 推导一个新对象或规则，展开字段、所有者、生命周期和提交边界。
4. 用正常 trace 与失败 trace 验证新结构。
5. 再增加规模、并发、阻塞或崩溃条件，推导下一层结构。
6. 所有局部结构建立后，再给端到端链路和综合练习。

完整对象图、跨层调用链和现代实现对比只能出现在综合位置，不能作为零基础章节的开场。优化必须由基本方案的具体成本推导出来。

## 样本先行

对全书逻辑起点或章节演进进行重大改造时，先在独立样本书中实现少量连续章节，不修改现有
正式书稿。每形成一个新阶段，向用户说明当前机器已有状态、暴露的问题和下一项机制，等待
用户继续指导。样本通过后，才把经确认的结构迁入正式书。

## 第一部分：执行与内核边界

### 第 1 章：为什么需要操作系统对象

从一个程序独占处理器、内存和设备的朴素机器开始。依次加入第二个程序、程序失控、设备延迟和程序退出，逐步得到受保护的内核、资源身份、执行状态、等待关系和生命周期。文件保存全链路移动到章节末尾，作为对象已经建立后的第一次综合验证。

### 第 2 章：为什么执行流需要 task 与调度状态

从“暂停一条指令流后怎样继续”开始，先得到最小现场，再分离线程私有现场与进程共享资源。随后加入多个可运行任务、阻塞条件、多核和优先级，依次得到 task、内核栈、runqueue、wait queue、调度策略和迁移规则。完整上下文切换只在两类现场都已推导后出现。

### 第 3 章：为什么用户请求需要受控入口

从用户程序想执行一个自己无权执行的动作开始。先得到最小请求编号和返回约定；再因用户栈不可信得到内核栈和入口帧；因处理函数很多得到分发表；因地址属于用户空间得到复制与故障修复；因对象可能并发变化得到稳定引用；因主体权限不同得到凭据、能力和策略钩子；因操作会阻塞得到等待、信号和重启；最后推导返回检查、兼容层、批处理与快速路径。完整系统调用链只能放在这些结构之后。

### 第 4 章：为什么一组程序字节还不是可运行映像

从一个包含机器码的文件开始，依次遇到格式识别、地址冲突、段权限、参数传入、动态依赖和失败回滚，推导 ELF 头、program header、VMA、初始用户栈、辅助向量、解释器和 exec 提交点。

### 第 5 章：为什么共享状态需要同步与通信对象

从两个执行流修改一个计数器开始，先推导原子性和临界区，再加入等待、多个资源、读多写少和进程边界，得到锁、等待队列、条件变量、信号量、RCU 与 IPC。死锁和优先级反转由具体交错推导，不先列四个条件。

## 第二部分：地址空间与内存

### 第 6 章：为什么地址不能直接等同于物理位置

从两个程序都想使用同一地址开始，推导独立地址空间；再由连续区间、按页权限、未映射访问和复制成本得到 VMA、PTE、page fault、COW、回收与交换。多级页表和 TLB 是规模成本的优化，不作为开场术语。

### 第 7 章：为什么文件内容需要可共享的内存身份

从重复读取同一文件页开始，先得到按文件偏移索引的缓存页；再由地址访问、共享写、私有写、回写和截断得到 mmap、page cache、dirty/writeback、COW 与失效规则。直接 I/O、DAX 和异步缺页由缓存路径的代价推导。

### 第 8 章：为什么内核还需要自己的分配器

从内核临时需要一个对象开始，先得到物理页分配；再由连续性、大小差异、频繁复用、上下文限制和碎片得到 zone、buddy、slab、per-CPU cache、GFP 规则和压缩。调试器由生命周期错误推导。

## 第三部分：设备、文件与网络

### 第 9 章：为什么设备操作需要长期请求对象

从一次寄存器操作无法等待设备完成开始，得到请求身份、buffer 所有权和 completion；再加入队列并行、中断成本、DMA、超时、复位和移除，推导描述符环、下半部、IOMMU 与设备生命周期。

### 第 10 章：为什么不同设备请求需要公共块层与文件接口

先从固定大小的块请求开始，推导拆分、合并、排序和多队列；再由持久化顺序得到 flush/FUA。块层稳定后，才引入 fd、打开文件对象和 VFS 分发，把“设备块”提升为“可被进程引用的对象”。完整文件 I/O 链放在章末。

### 第 11 章：为什么可寻址块还不能组成文件系统

严格按“持久字节 → 固定块 → 空闲记录 → 文件身份记录 → 名称映射 → 重新挂载所需的全局说明 → 最小磁盘布局”推导。inode、目录项和超级块只能在对应问题出现后命名，并逐字段说明为何独立存在。

### 第 12 章：为什么最小文件系统需要索引与局部性优化

从最小布局在大文件、大目录和大容量设备上的线性成本出发，依次推导直接/间接块、extent、分层位图、块组、目录 hash/B-tree 和 VFS cache。每项优化都保留基本方案作为对照并计算成本变化。

### 第 13 章：为什么运行正确还不足以抵抗崩溃

从 create、unlink、rename、truncate 的最小更新集合开始，先处理运行期锁与回滚；再逐个断电点观察磁盘状态，推导写回顺序、日志事务、checkpoint、fsync 和 COW 根切换。缓存与持久化边界不能混为一体。

### 第 14 章：现代文件系统为什么做出不同取舍

只在前述基本结构、索引和恢复协议已经建立后比较 ext4、XFS、Btrfs、ZFS、F2FS、NTFS 与 APFS。每个系统围绕同一组工作负载、失败模型和提交边界展开，不做无因果关系的特性罗列。

### 第 15 章：为什么网络通信需要持久端点

从一次数据报无法表达长期会话开始，推导 socket 身份、地址绑定、监听队列、连接状态、发送/接收缓冲和背压；再加入丢包、关闭、并发和设备队列。完整网络收发链放在这些对象建立之后。

## 第四部分：安全、可靠性与观测

### 第 16 章：为什么“已经隔离”仍不等于最小权限

从一个主体访问一个对象开始，先得到主体、对象和操作三元关系，再加入继承、容器视图、资源消耗和强制策略，推导 DAC、capability、namespace、cgroup、LSM 和 seccomp。

### 第 17 章：为什么“写成功”仍不等于可恢复

从内存可见的新值开始，逐层增加缓存、设备重排、撕裂写和多对象更新，推导持久化顺序、WAL、manifest、checkpoint、校验和、镜像与恢复幂等性。

### 第 18 章：为什么症状不能直接说明原因

从一个用户可见错误开始，区分错误传播、oops 与 panic；再由证据缺口推导指标、事件、调用链、转储和故障注入。最终综合 trace 在这里连接全书，但每种证据必须先说明能证明什么、不能证明什么。

## 章节完成标准

- 开场不出现未经推导的全景图或跨层链路。
- 每个核心名词都有前置失败条件和结构必要性。
- 每项优化都能回指基本方案的可量化成本。
- 完整链路只在局部对象全部建立后出现。
- 每章至少约 50 个有效正文 PDF 页，并以知识链闭合而非页数停止。
