# 操作系统书逐章扩写与发布流程

## 0. 同步实时项目主线

1. 运行 `scripts/audit_project_sync.py`。
2. 若项目指纹或完成边界变化，按 `project-sync-workflow.md` 审计实时项目并运行完整验证。
3. 先同步贯穿案例、部分过渡和受影响章节入口，再开始本轮扩写或排版工作。
4. 记录当前完成里程碑、正在实现边界、未来路线和验证结果。不得只更新快照。

## 1. 建立章节基线

1. 检查工作树、当前分支和远端，保留无关修改。
2. 阅读 `source/latex/main.tex`、目标章节及其所有直接和间接输入文件。
3. 从现有 PDF、目录和书签确定章节首页、正文终点、练习与答案范围，分别记录有效正文页数和全章页数。
4. 列出现有知识单元、结构图、字段表、trace、边界条件、练习与答案。扩写时默认保留这些单元。
5. 选择一条可以贯穿全章的真实操作作为主线，并写出读者在章末应能独立追踪的完整路径。

## 2. 形成扩写账本

按“问题 → 所需状态 → 对象与字段 → 路径 → 边界 → 失败/恢复 → 图示 → 练习”拆分机制单元。每个单元至少回答：

- 简单做法在哪个具体条件下失效？
- 新对象为何必须独立存在，不能并入已有对象？
- 对象保存哪些代表性字段？字段由谁写入、读取和保护？
- 一次正常路径中字段如何逐步变化？
- 哪个事件让结果对谁可见？这是否等于完成或持久化？
- 并发、取消、超时、部分完成或崩溃时怎样收束？

标记哪些内容适合正文、对象图、栈布局、前后快照、泳道、短字段表、演算例或练习。先分配页面和图形空间，再绘制细节。

## 3. 写作与结构

1. 先写具体情境和已有状态，再引入第一个新概念。
2. 概念首次出现后立即给出其职责、非职责、生命周期和与相邻对象的边界。
3. 每个核心路径至少提供一个带具体初值的逐步 trace。
4. 异步或可阻塞路径同时展示执行流状态与请求对象状态，不能只画其中一侧。
5. 某体系结构或内核实现的具体例子要与稳定的操作系统语义分开表述。
6. 在章节末尾回到开篇操作，逐对象、逐字段、逐边界完成端到端复盘。
7. 达到至少约 50 个有效正文 PDF 页；若知识链尚未闭合，继续扩写而不是停止在页数线。

## 4. 图表与页面

- 为每张图先写一句必须证明的技术命题，再选择布局。
- 结构关系采用对齐层级；时间关系采用泳道；状态转换采用有限状态图；字段解释采用短表或带注释布局。
- 先确定列中心、行基线、节点宽度和留白，再加箭头。箭头尽量短且水平或垂直。
- 表格使用明显的纵横分隔线；超过一页或字段过多时按语义拆分。
- 图表前后必须有正文承接，不允许连续堆放没有推导的图表。

## 5. 内容与排版验收

从仓库根目录执行书稿已有检查和生成目标。然后：

1. 检查日志中的错误、未解析引用、overfull/underfull 异常和缺失字形。
2. 从最终 PDF 重新测量目标章节有效正文页数和全章页数。
3. 将章节开头、每张新增图、所有表格、结构最密集页、跨页过渡和章末渲染为图片并目视检查。
4. 逐图确认文字不重叠、连线不穿越节点、标签可读、留白充分且图文结论一致。
5. 逐表确认手机尺寸可辨认的横纵线、合理列宽和分页。
6. 搜索用户禁止的口语与暴力隐喻；抽查高频过渡语，改写机械重复。
7. 对照扩写账本确认：对象字段、所有权、生命周期、正常 trace、并发边界、提交点、失败/恢复、练习答案均已覆盖。
8. 运行 `python3 .codex/skills/operating-systems-book-architecture/scripts/normalize_table_grid.py --check`，确认所有可达正文表格都有外框、纵向分隔和逐行横线。

构建成功但任一内容或视觉检查失败，都不能宣布章节完成。

## 6. 导出、提交与推送

1. 运行操作系统书的手机导出目标。
2. 比较 `source/latex/main.pdf` 与手机目录中的 PDF 哈希。
3. 检查 `git diff --check` 和最终工作树。
4. 仅暂存本轮修改的 `books/operating-systems-volume-1` 与 `.codex/skills/operating-systems-book-architecture` 文件。
5. 提交当前分支并推送到其配置远端。
6. 验证本地 HEAD 与远端分支 tip 一致。
7. 向用户报告：章节有效正文页数前后变化、主要新增机制与图示数量、检查结果、导出位置、哈希、提交和推送状态。
