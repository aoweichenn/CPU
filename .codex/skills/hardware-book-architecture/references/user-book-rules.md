# 《硬件从零到整机》用户硬性规则

本文件汇总用户在持续编辑对话中明确提出的规则。每次触发 `hardware-book-architecture` skill 都必须完整加载，不依赖会话记忆，也不因任务较小而跳过。

## 内容与架构

- 全书保持七部分、二十六章的目标结构。压缩章节容器不能减少任何既有正文、图表、公式、代码、案例、练习、答案或检查项。
- 从零建立完整硬件通路：电平与器件 → 逻辑与状态 → ISA、CPU 与提交 → 存储层次 → 互连与设备事务 → 主板、固件与平台 → 整机 trace 和故障恢复。
- 存储系统必须作为连续的大部分完整讲解，覆盖存储单元、Cache/TLB/DRAM、NAND/SSD/NVMe、磁盘/SATA、文件与块 I/O、DMA、接口协议、持久化、可靠性和端到端 trace；内容可继续丰富，不得缩减。
- 扩写不能只增加名词或篇幅。每个机制至少说明输入/状态、数据路径、控制决策、时序或提交边界、可见结果以及错误/恢复。

## 规则存放位置

- 架构、编辑、排版、审计、导出和发布规则只写入本 skill，不写进书稿、前言、章节或检查表。
- 书稿中只保留读者需要看到的内容；不得暴露“旧稿”“迁移规则”“用户要求”或内部工作流。

## 文字与术语

- 全书文字要持续统一和优化，但任何润色都不能删减知识内容、数值、边界条件或案例。
- 使用正式、准确、自然的技术措辞和明确因果过渡。禁止用“逼出了”“逼出”“吃掉”“喂给”“兜底”“饿死”“一招”“随手”等口语、强迫或暴力隐喻替代机制说明。
- 不用含混的“上一节”“下一节”或过时章号导航；引用稳定的当前主题名或章节名。

## 插图与连线

- 每轮涉及插图的工作都要对全书相关图片做 PDF 视觉自检，不能只检查 LaTeX 源码或编译是否成功。
- 图中文字不能互相重叠；连线不能穿过文字或节点；多条线不能在无语义的情况下重叠；箭头、标签和返回路径必须可区分。
- 图不要拥挤。节点、文字、连线和图边界之间保留宽松间距；优先改为分层、分行或分图，不以缩小字体掩盖拥挤。
- 坐标图必须给曲线留出明确的上下左右余量；曲线、柱形、阈值线和控制点不得越过绘图区或坐标轴箭头。负值、断轴、对数轴和归一化轴必须明确标出范围与零点，不能依靠读者猜测。抽象曲线要补足单位、关键刻度、图例、参考线和读图提示，使零基础读者能从图中直接读出变量、边界与结论。
- 修改图后至少渲染并查看受影响 PDF 页面，同时检查越界框和缺字日志。

## 表格、检查表与长表

- 正文表格和章末/书末检查表必须有明显、连续、对比度足够的分隔线。相邻行使用清楚的横线，相邻列使用清楚的竖线；不能只依赖浅色底纹、留白或过细的线。
- 表格线要在普通 PDF 缩放和手机阅读尺寸下仍可辨认。验收时必须渲染实际页面检查，不以存在 `\hline`、`booktabs` 命令或编译成功代替视觉确认。
- 章末练习和参考解答不得以表格呈现。采用类似 CS:APP 的教材式连续题目：独立编号、题型/标题、题干，以及分开的编号解答。
- 习题数量保持克制。每章原则上保留 6--10 道编号核心练习；既有题目超过该数量时，不删除题干、边界条件或答案，而应按机制合并为综合题的清晰子题，或转为正文例题、选做实践。不要为了“丰富”继续堆叠同类练习。
- 特别长、内容密集或接近整页的表格要按语义拆分，重复表头，并在每段前后补充解释、结论或阅读指引。避免连续页面只有表格而没有正文承接。
- 拆表不能删除行、列或信息，也不能把本应并列比较的字段拆散到无法对应的位置。

## 代码与伪代码

- 全书所有伪代码都要有教学注释。注释至少说明状态/所有权怎样推进，以及完成、提交、失败或恢复边界。
- 不把公式、真实 Verilog/C/汇编、终端输出或数据布局误标为伪代码；这些内容保留其本来类型和必要注释。

## 字体与构建

- 优先保证 Maple 字体完整可用；发现缺失字形或字体文件时，先检查并安装/配置合适字体，再验证 PDF 中无缺字。
- 发布前检查输入图、旧内容基线、伪代码注释、措辞、表格、图形、LaTeX 日志和 PDF 实际页面。不得只以脚本退出码判断排版合格。

- 只暂存本书与本 skill 的相关文件，保留无关工作树内容；提交当前分支，推送到已配置远端，并验证本地与远端分支 tip 一致。
